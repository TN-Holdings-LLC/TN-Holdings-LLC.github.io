Quantum circuits built by formula, run on real devices without the calibration map.

We build a compiler that places and schedules circuits by formula instead of search, and a self-checking layer that runs users' circuits on IBM heavy-hex devices and says how far each answer can be trusted. Everything is open, and every device result was declared before its data existed.

How we test

The same four rules for every result, including the ones that did not go our way.

Projects

Four open repositories.

compiler

PSF-Zero

A Qiskit-compatible compiler that builds circuits by formula, with no search: chains, rings and lattices that embed in the device, and the device's native fractional gates. Every other circuit is refused with a reason. Templates build once and rebind angles in about a millisecond, for training loops.

operating layer

psf-os

A self-checking layer between a user's circuit and an IBM heavy-hex device: it places the circuit by formula, adds a floor, a mirror and a ring sentinel to the same job, keeps a list of what it found dead, and returns an answer card. It reads the coupling graph and the failed elements, never a calibration quality number. Since 0.2, real-time control: circuits that measure in the middle and act on the result while they run, each with its uncontrolled twin in the same job, and a loop that picks the next round's circuit unattended. Release 0.2.0 (2026-11-19); DOI 10.5281/zenodo.24367846 (all releases: 10.5281/zenodo.24211404).

records

psf-os-lab-notebook

The declared device tests behind the papers: each declared before its calibration was fetched, answers sealed until the verdicts, raw counts committed, every result re-scorable with python reproduce.py. It also keeps the original task-oriented compiler benchmark.

metric

readable-depth

How deep a circuit stays readable on a raw device, per problem family: the definition (a result reads when at least half of the signal's squared size survives), a small scorer, and the boundary table built from the notebook's records.

What psf-os does differently

Qiskit and IBM Runtime aim to give any circuit the best value they can: layouts scored with the day's error rates, results corrected by mitigation. psf-os aims to say how far a value can be trusted, for the circuit shapes it knows.

  • No calibration map. Placement reads the coupling graph and the failed elements, never an error rate: the same circuit lands on the same qubits whatever the day's calibration says, so a run can be declared before the calibration is fetched and results compare across days.
  • Checks in the same job, reported, never used to correct. A floor, a mirror, a ring sentinel and the Clifford twin (the same pulses, with an exact answer at any size) run beside the user's circuit; the answer card says whether the result reads and how much of the signal the device kept.
  • A defect list of its own. Elements its scans find dead, including defects the calibration does not show, are registered and avoided from then on.
  • Refusal with a reason. A circuit that touches a failed element is not sent; a shape the entrance does not recognise is refused, with the reason.
  • Records anyone can re-score. Sealed answers, raw counts and one command (python reproduce.py): 34 of 34 results re-scored the same from fresh clones on 2026-11-14.

What it does not do: general circuits (only chains, rings, 2D lattice patterns and 4 × M × N cubic lattices, on IBM heavy-hex devices); error mitigation, so deep circuits often come back as “does not read”; anything a wide user base has tested yet (release 0.1, used by its authors).
